아키텍처 하이라이트

TSet / TMap — 해시 버킷 인덱스 체인

원소는 TSparseArray에 저장되어 삭제 후에도 인덱스가 안정적이고, pow2 버킷 배열은 해시별 첫 원소 인덱스만 보관한다. 충돌은 원소 내 m_HashNext 인덱스로 체인 연결. 삭제는 체인 unlink + 슬롯 반납으로 O(1), 톰스톤 없음 — Open Addressing 방식에서 발생하던 삭제 표식 누적·불필요한 Rehash 문제를 원천 해결했다.

buckets[hash & (N-1)] ──▶ [3] ──m_HashNext──▶ [0] ──▶ INDEX_NONE
                             └ 같은 버킷의 원소들이 인덱스 체인으로 연결
Rehash: 원소는 그대로, 버킷 배열만 새로 만들어 인덱스 재링크 (원소 이동 0회)

FMallocBinned — 포인터 마스킹 기반 O(1) 할당자

16~512B 크기 클래스 Bin을 64KB 정렬 페이지에서 잘라 쓴다. 해제 시 ptr & ~(PAGE_SIZE-1) 마스킹 한 번으로 소속 페이지 헤더를 역추적해 Bin을 알아내므로, 블록별 헤더 오버헤드가 0바이트다.

┌────────────┬──────┬──────┬──────┬─ ─ ─┐   64KB 정렬 페이지
│ PageHeader │ 블록0 │ 블록1 │ 블록2 │ ... │   (Bin 크기로 분할)
└────────────┴──────┴──────┴──────┴─ ─ ─┘
Free(ptr):  ptr & ~(65536-1)  →  페이지 헤더  →  Bin 인덱스  →  프리 리스트 반납

TSharedPtr — 암묵적 Weak 참조로 순환 참조 이중 해제 방지

컨트롤 블록의 WeakCount를 1로 초기화해 "공유 소유자 그룹 전체"의 암묵적 weak 참조를 표현한다. 마지막 Shared 해제 시 Deleter가 실행되는 도중 멤버 TWeakPtr들이 자기 몫을 반납해도 그룹 몫 1이 블록을 지켜주며, Deleter 완료 후에야 그룹 몫까지 반납되어 블록이 해제된다 — std::shared_ptr와 동일한 패턴으로, 실제 겪은 Release 전용 이중 해제 버그를 해결했다.

트러블슈팅 하이라이트

① TSharedPtr 순환 참조 — Release 전용 힙 손상 (0xC0000374)
증상
Debug는 통과하나 Release에서 순환 참조 테스트가 힙 손상으로 크래시
원인
파괴 중 Deleter 체인 안에서 TWeakPtr가 컨트롤 블록을 먼저 해제 → 이중 해제. Debug 힙의 0xDD 채움이 우연히 증상을 가려 Release에서만 노출
해결
WeakCount를 1로 초기화하는 암묵적 weak 참조 패턴 도입(std::shared_ptr와 동일)
② MSVC Debug 인라인 코드생성 버그 (FName::ToString)
증상
값 반환 시 접근 위반. 함수 내부를 3회 재구성해도 크래시 위치·값이 완전히 동일
원인
콜스택에 해당 함수 프레임이 한 번도 없음 → /Od에서도 초소형 함수가 인라인되어 소스 수정이 생성 코드에 반영 안 됨
해결
함수를 .cpp로 분리 + noinline 지정 → 진짜 함수 호출 경계(x64 ABI) 강제로 즉시 해결
③ Release NDEBUG에서 check() 부수효과 증발 (0xC0000005)
증상
Release에서만 컨테이너 연산이 null 근처 주소 쓰기 위반
원인
check() 안에 넣은 상태 변경 호출이 NDEBUG에서 표현식째 컴파일 제거 → 빈 컨테이너에 후속 연산 실행. 크래시 주소를 슬롯 오프셋 계산과 대조해 수치로 확정
해결
상태 변경을 독립 문장으로 분리하는 규약화 + 검증 파이프라인에 Release 등가(NDEBUG) 구성 상시 포함
